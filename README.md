# xlauncher

Лаунчер изолированных профилей Chromium для Windows: свои куки, отпечаток и прокси у каждого профиля, перенос профиля копированием папки, управление через API/MCP и доступ ИИ-агента к браузеру через CDP.

Спецификация — [ARCHITECTURE.md](ARCHITECTURE.md).

## Статус

- [x] Этап 1 — проверка рисков (`spike/`)
- [x] Этап 2 — автообновления: загрузчик, CI-релизы, установка и откат
- [x] Этап 3 — ядро и раннер: профили, прокси, запуск (простой интерфейс)
- [x] Этап 4 — интерфейс, проверка уникальности отпечатков
- [x] Этап 5 — MCP и управление браузером агентами (локально)
- [ ] Этап 6 — импорт, загрузка движка и геобазы

## Установка

1. Создай пустую папку, например `C:\xl`. В ней будет жить всё: программа, профили, журналы.
2. Скачай [xlauncher.exe](https://github.com/susoev/xlauncher/releases/latest/download/xlauncher.exe) в эту папку.
3. Запусти. Windows может показать «Система Windows защитила ваш компьютер» — «Подробнее» → «Выполнить в любом случае» (один раз).

При первом запуске загрузчик скачает последнюю версию приложения (~20 МБ) и откроет окно.

Дальше обновления ставятся сами: каждый push в `main` собирается в GitHub Actions, и запущенный лаунчер в течение 15 минут скачивает новую версию и перезапускается. Если новая версия не запустилась, загрузчик откатывается на предыдущую.

### Подпись

Exe подписаны собственным сертификатом (`CN=susoev`, открытая часть — [`build/codesign.cer`](build/codesign.cer)). Чтобы Windows показывал издателя «susoev», один раз на каждом ПК в PowerShell **от администратора**:

```powershell
$c = "$env:TEMP\xlauncher-codesign.cer"
Invoke-WebRequest https://raw.githubusercontent.com/susoev/xlauncher/main/build/codesign.cer -OutFile $c
(Get-PfxCertificate $c).Thumbprint   # должно быть 0A8BFF4231F62F729EE693DF0DD9E34447F12CAE
Import-Certificate $c -CertStoreLocation Cert:\LocalMachine\Root
Import-Certificate $c -CertStoreLocation Cert:\LocalMachine\TrustedPublisher
```

Сертификат годится только для подписи кода (`CA:FALSE`, EKU codeSigning) — выпускать другие сертификаты или подменять сайты он не может. Без этого шага всё работает как раньше, просто издатель «неизвестный».

## Устройство папки

```
C:\xl\
  xlauncher.exe          загрузчик (меняется редко, обновляется сам)
  app\<версия>\          приложение: встроенный Python + код
  app\current.txt        активная версия
  app\previous.txt       предыдущая — для отката
  app\bad.txt            версии, которые не запустились
  run\                   служебные файлы работающего приложения
  logs\                  bootstrap.log, app.log
```

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest -q                      # тесты приложения
(cd bootstrap && go test ./...)          # тесты загрузчика
cd src && python -m xlauncher            # запуск из исходников (без автообновлений)
```

## Управление агентами с другой машины

XLauncher может принимать подключения агентов (например, Claude Code на VPS) по MCP через Tailscale.

1. На компьютере с XLauncher установи [Tailscale](https://tailscale.com/download/windows) и войди в тот же аккаунт, что и на машине агента.
2. XLauncher → «Настройки» → «Удалённый доступ для агентов» → «Включить». Там же — «Запускать вместе с Windows», чтобы агент мог подключаться после перезагрузки.
3. Скопируй готовую команду и выполни её на машине агента:
   ```
   claude mcp add --transport http xlauncher-<компьютер> http://100.x.x.x:47111/mcp --header "Authorization: Bearer <токен>"
   ```
4. Проверка: попроси агента вызвать `machine_info`.

Порт слушает все интерфейсы, но пропускает только адреса Tailscale и локальный компьютер, и только с токеном. После копирования папки лаунчера на другой компьютер выпусти там новый токен.

Каждый профиль должен «жить» на одном компьютере: если открывать копии одного профиля на двух машинах, у них разойдутся куки. В карточке профиля видно, если последний запуск был на другом компьютере.
